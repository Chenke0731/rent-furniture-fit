# 访谈与对照实验操作手册

供需求发现（第 1—2 个月）与用户对照实验（第 10—11 个月）主试人员使用。

## 一、 探索性访谈提纲（建议先行完成 10 次）

访谈重点是**真实购买决策与踩坑经历**，不要直接问“你喜不喜欢这个界面”。

1. 最近一次给租来的房子买书桌、置物架或收纳柜，当时怎么确定尺寸的？有没有量门宽、踢脚线或前方拉椅空间？
2. 有没有买回来才发现放不下、进不了门、房东不让打孔或搬家带不走的情况？当时漏看了哪个信息？
3. 在两三款价格接近的商品之间犹豫时，最后是什么因素让你做决定的？哪些参数详情页经常找不到？
4. （展示原型试跑）在“适配审核单”里，你第一时间看懂哪些项？有没有注意到底部的“买前需确认”提示？

## 二、 对照实验操作步骤（约 40—60 名参与者）

### 1. 实验设计

- 每位参与者依次完成两个选购任务（`T1` 书桌、`T2` 置物架或收纳柜），分别在两种界面条件下完成：
  - **条件 A（普通商品列表）**：展示与电商详情页一致的参数表，由参与者自行判断。
  - **条件 B（适配审核单）**：展示硬约束检查结论、依据、待确认项与偏好排序。
- **顺序平衡**：系统在 [tasks.ts](../src/data/tasks.ts) 中按参与者编号自动分为 4 组，平衡条件 A/B 的先后顺序与任务搭配。

### 2. 现场执行流程

1. 给参与者分配连续正整数编号（`1, 2, 3...`），不要跳号。
2. 在小程序首页点击底部的 **“实验模式 · 对照任务与数据导出”**。
3. 输入参与者编号，核对屏幕显示的分组与任务顺序后点击 **“开始任务”**，系统自动开始计时。
4. 参与者独立阅读房间条件并选出 1 款家具，提交后完成 2 道 1—5 分评分题（理解度、满意度），再自动进入第二个任务。
5. **重要提示**：每台设备收集完当天或全部参与者后，在“实验模式”页面点击 **“导出 CSV”**，及时把数据文件备份给统计分析成员，避免清理浏览器缓存导致记录丢失。

### 3. 导出 CSV 字段说明

| 字段名 | 说明 |
| --- | --- |
| `participant` | 参与者编号 |
| `group` | 顺序平衡组别（1—4） |
| `step` | 第几步任务（1 或 2） |
| `taskId` | 任务编号（`T1` 或 `T2`） |
| `condition` | 界面条件（`A` 普通列表 / `B` 适配审核单） |
| `startedAt` | 任务开始时间（ISO 时间戳） |
| `durationSec` | 从打开任务到确认选择所用时间（秒） |
| `selectedId` / `selectedName` | 参与者最终选中的商品 |
| `selectedStatus` | 所选商品在规则引擎中的客观状态（`fit`/`conditional`/`conflict`/`insufficient`） |
| `isError` | 是否误选了存在硬冲突的商品（`true`/`false`，主要观察指标） |
| `expandCount` | 在条件 B 下展开查看“已满足硬条件”的次数 |
| `understanding` / `satisfaction` | 任务后理解度与满意度自评分（1—5） |
