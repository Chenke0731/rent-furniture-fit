# 商品参数数据录入规范

供数据与调研负责人、交互与参数负责人录入 100—150 款人工核验商品时使用。填表模板为根目录 [data-template.csv](../data-template.csv)。

## 1. 录入原则

- **如实留空**：电商详情页或品牌官网未披露的参数必须留空，禁止估算或替商家填补。系统依赖空值触发“信息不足”或“有条件适配”提醒。
- **单位统一**：尺寸全部以厘米（cm）填写，价格、运费与安装费以元填写，重量以千克（kg）填写，只填数字，不带单位文字。
- **记录来源**：每款商品必须填写来源平台或品牌名称及核验日期，以便后续复查参数变动。

## 2. 字段说明

| 列名 | 含义 | 允许值与格式 | 核验要点 |
| --- | --- | --- | --- |
| `id` | 商品唯一编号 | 字母加数字，如 `D001`、`S001`、`C001` | 全表不可重复 |
| `name` | 商品名称 | 文本 | 写明品牌或款式核心尺寸，便于对照识别 |
| `category` | 家具品类 | `书桌`、`置物架`、`收纳柜`（或 `desk`、`shelf`、`cabinet`） | 仅限首版三类 |
| `price` | 商品标价 | 数字（元）或留空 | 取核验当日页面到手价 |
| `extraFee` | 运费与安装费合计 | 数字（元）或留空 | 包邮且自装填 `0`；页面写偏远另议或未写则留空 |
| `width` | 成品宽度 | 数字（cm）或留空 | 左右总宽 |
| `depth` | 成品深度 | 数字（cm）或留空 | 前后纵深 |
| `height` | 成品高度 | 数字（cm）或留空 | 含桌腿或顶板总高 |
| `packageMinSide` | 外包装最短边 | 数字（cm）或留空 | 看“包装尺寸”三边中的最小值；未标则留空 |
| `operationDepth` | 前方使用所需空间 | 数字（cm）或留空 | 抽屉完全拉出深度、柜门开启半径或书桌坐姿预留 |
| `needsDrill` | 是否必须打孔固定 | `是`、`否`（或 `yes`、`no`），未知留空 | 防倾倒上墙或壁挂安装若必须打孔填 `是` |
| `assembly` | 拆装方式 | `整装`、`需工具`、`免工具`（或 `assembled`、`tool`、`toolfree`），未知留空 | 整箱发成品填 `整装`；配螺丝内六角填 `需工具`；折叠或卡扣填 `免工具` |
| `weight` | 净重或毛重 | 数字（kg）或留空 | 优先填包装毛重，其次净重 |
| `source` | 数据来源 | 文本 | 例：`宜家官网`、`淘宝某旗舰店` |
| `checkedAt` | 人工核验日期 | `YYYY-MM-DD`，例 `2026-11-20` | 留空会被系统标记为示例数据 |

## 3. 批量校验与导入步骤

1. 将表格另存为 **UTF-8 编码的 CSV 文件**（Excel 另存时选择“CSV UTF-8 (逗号分隔)”）。
2. 在项目根目录执行校验，检查报错和缺失项统计：

```powershell
node scripts/import-csv.mjs 你的商品表.csv
```

3. 确认解析无误后写入系统商品库，再运行单元测试确认兼容：

```powershell
node scripts/import-csv.mjs 你的商品表.csv --write
npm test
```
