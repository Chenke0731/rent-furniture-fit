# 规则核验清单

供第 8—9 个月规则核验阶段使用，由团队外人员与团队成员共同核对算法输出是否符合人工常识判断。

## 1. 核验指标定义

| 指标 | 计算方式 | 目标要求 |
| --- | --- | --- |
| 错误推荐率 | 人工判定存在硬冲突，但系统输出为“适配”或“有条件适配”的案例占比 | 应为 0 |
| 错误排除率 | 人工判定实际可放入且不违约，但系统输出为“冲突”的案例占比 | 尽量压低，记录具体阈值原因 |
| 信息不足识别率 | 关键参数缺失且无法替代推导时，系统准确输出“信息不足”或“有条件适配”提示的比例 | 不因价格低或偏好高而漏报 |

## 2. 判定优先级规则

系统按以下顺序决定单件家具的最终状态（实现见 [evaluate.ts](../src/engine/evaluate.ts)）：

1. **冲突**：存在任意一项明确超出空间尺寸、搬运门宽、预算上限或违反打孔限制的情况。即使同时缺少其他参数，也直接判为“冲突”。
2. **信息不足**：无已知硬冲突，但存在无法判断的必检缺失项（例如整装不可拆却未披露包装尺寸、房东禁止打孔但商品未披露是否需要打孔、租房档案必填项缺失）。
3. **有条件适配**：硬条件全部满足且无关键缺失，但存在临界风险或买前待确认项（例如尺寸余量小于 2 cm、拆装家具未披露包装尺寸、短租不足 6 个月却选整装款、运费未披露）。
4. **适配**：全部已填约束满足且无上述风险提示。
